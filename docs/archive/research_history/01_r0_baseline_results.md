# STHGCN 实验成果与结果台账

## 1. 文档用途

本文记录 STHGCN 与后续 HC-Shared-MoE、LLM 教师模块的正式实验结果。所有结论必须来自实际日志、配置、checkpoint 或逐样本预测文件。缺失证据统一标记为 `[NEEDS DATA]`。

当前实验命名：

- R0：原始 STHGCN，可复现服务器基线。
- R1：STHGCN + Hypergraph-Conditioned Shared Sparse MoE，第一版已完成单种子 NYC 实验。
- R2：R1 + 规则教师，尚未实现。
- R3：R1 + LLM 离线教师，尚未实现。

开发阶段默认遵循单城市、单种子策略：优先 NYC，固定 `seed=80786525`。多种子仅在最终结构冻结后补做。

本轮继续使用 NYC、固定种子 `80786525`、Top-2、rank 32 和残差缩放 0.5。先执行 3000-step 单 Adapter 短跑，再严格比较以下两组 8 专家正式实验：

A1 相对 R1.2 将最大 Top-1 专家占比从约 30.88% 降至 22.57%，并恢复为 8/8 专家均有 test 流量；但 Recall@20 从 0.6837416 降至 0.6674091，只剩 Recall@10 高于 R0。观察表明，固定权重 0.01 的负载均衡能解决路由利用率问题，但约束偏强，损伤了原有长列表覆盖收益。

A2 在 warm-up 后得到 7 个冻结组：`[[0, 5], [1], [2], [3], [4], [6], [7]]`。它相对 A1 的 Recall@1/5/10/20 分别提高 0.0051968、0.0059391、0.0044544、0.0051968，MRR 提高 0.0034767；最大 Top-1 专家占比为 23.39%，8/8 专家均有流量。自适应分组因此在维持较均衡路由的同时，恢复了 A1 损失的一部分推荐效果。

A2 相对 R0 的 Recall@10 与 Recall@20 分别提高 0.0103935 和 0.0037120，达到开发期 `2/4` 小成功；但 Recall@1、Recall@5、NDCG、MAP 和 MRR 仍低于 R0。A2 相对 R1.2 的 Recall@1 和 MRR 分别提高 0.0074239 和 0.0031479，但 Recall@20 低 0.0111358。当前结果支持“分组有益于均衡与头部恢复”，不支持“已经全面优于原 8 专家方案”。

## 5. 当前结论

R0 的 NYC 基线已经完成并作为固定门槛。R1、R1.1、R1.2 与 A2 均按 Recall@1/@5/@10/@20 四项二过四口径取得单种子开发期小成功，稳定信号仍是 Top-10/Top-20 覆盖提升。

当前存在明确取舍：R1.2 的 Recall@20 最高，但存在死专家和低流量专家；A3 的 Recall@1 最高，12/12 专家全部活跃，最大 Top-1 占比降至约 13.96%，MRR 与 R0 只差 0.00189，但 Recall@5/10 不及 R0 和 R1.2。分组前 0.01、分组后 0.003 的负载权重已经兼顾了均衡与专业化，没有必要继续做密集参数搜索。下一步应先根据论文主目标在“R1.2 的长列表覆盖”和“A3 的头部排序、完整专家利用”之间确定主模型，再决定是否进入跨城市验证或离线教师阶段。
